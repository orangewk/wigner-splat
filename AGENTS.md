# Project Agent Notes

- Before retrying a hung pytest run, do not start a second pytest process; first inspect/stop the original process and record the hang diagnosis.
- When stating what an external licence, standard, or paper says, fetch the primary source and quote only what you verified there; a search snippet or a plausible paraphrase is not a source. (2026-07: a zero-counting lemma was cited from a snippet and had to be withdrawn; the Tanks and Temples licence terms were recorded inaccurately for weeks.)
- Before deleting a branch or worktree, or promoting one into main, check its dirty state and the head of each changed file; publication status is sometimes recorded in uncommitted working-tree edits rather than in commits. (2026-07: a doc marked "Private, local only" in an uncommitted edit was merged into the public repo and had to be reverted.)
- Code that prints a verdict must compute it from the data. Never hard-code the conclusion in the output string. (2026-07: routeB.py printed "cutoff-stable" unconditionally; the claim propagated into the README and the archived preprint while the measured series was increasing.)
- A claim has exactly one authoring location. Everywhere else it is generated from that location or cited by reference — never restated by hand. This covers artifact JSON, README prose, figure labels, docs, and PR bodies alike; a matplotlib annotation string is an authoring location, and so is a sentence in an appendix that repeats a formula from the body. (2026-07: seven divergences in one day, all of the same shape — the fix landed on the copy that happened to be found. See `tests/test_claim_surface_policy.py` for the surfaces that are checked mechanically.)
- Scope qualifiers (mode count, dictionary restriction, epistemic status, which state a number describes) belong in a table with one row per claim, not in prose that enumerates section numbers. Prose enumerations silently omit rows added later; an empty table cell is visible. (2026-07: "Sections 4–5 and rows D2–D3 are single-mode" left §6 and D1/D4/D5 undeclared, and an external reviewer read the wrong mode count.)
- Before closing a review finding, grep every surface for the same claim and fix all of them in the same change. A finding is not one defect; it is one sighting of a defect that usually has copies. (2026-07: four of the seven divergences above were created by fixing only the sighted copy.)
- Do not schedule timed self check-ins to poll a pull request. Subscribing to its webhook activity is the whole mechanism: reviews, pushes, CI results, and state changes each wake the session on their own. A timer adds nothing but a full context reload per firing, and when the PR is waiting on a human it fires only to re-arm itself. Subscribe, then stop. (2026-08: 26 such check-ins across PRs #24, #138, #144, #165, #168, #171 and other repositories — every one found no change and scheduled the next.)
- The butler role (`docs/sebastian.md`) routes; it does not judge. Observations may be forwarded to an auditor, verdicts may not. (2026-08: two consecutive numerical dispatches passed a gate whose pass condition the butler had written, then verified, then diagnosed — each layer added by the role that should have been routing them to Sol.)
